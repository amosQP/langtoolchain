## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
TASK-140.1 스캔 결과: docs/shell-style-guide.md의 80자 라인 길이 규칙을 초과하는 라인이 39개 대상 .sh 파일 중 30개 파일에 걸쳐 229건 발견됨(81~325자, 대부분 spec 설명 문자열/에러·경고 메시지/상세 주석). TASK-140.2에서 '광범위하고 구조적'으로 분류해 직접 수정하지 않고 이 태스크로 분리함 — 30개 이상 파일을 손대는 대규모 리랩 작업이라 국소 스타일 수정 범위를 벗어나고, 문자열을 잘못 쪼개면 동작(특히 spec 설명·에러 메시지 가독성)이 바뀔 위험이 있어 신중한 개별 검토가 필요함.

권장 접근: 파일 단위로 순회하며 (1) URL/파일경로처럼 쪼갤 수 없는 예외는 그대로 두고, (2) 긴 printf/echo 메시지는 여러 printf 호출이나 변수 조합으로 분리, (3) 긴 주석은 줄바꿈, (4) spec 설명 문자열은 It '...' 축약 여부를 팀이 먼저 판단. 각 파일 수정 후 관련 shellspec을 돌려 통과 확인 필요. 위반 목록(파일:라인:길이)은 이 태스크를 맡는 세션에서 동일한 스캔 스크립트로 재현 가능(라인 길이는 UTF-8 문자 수 기준으로 세야 함 — macOS 기본 awk의 length()는 바이트 단위라 한글 주석이 섞인 라인에서 부정확한 값을 낼 수 있음, 반드시 python3 len() 등 문자 단위 카운터 사용).
